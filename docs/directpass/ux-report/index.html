Executive Summary

This report evaluates four major college and university websites, New York University (NYU), University of British Columbia (UBC), Northeastern University, and Conestoga College, through the lens of prospective international students navigating the discovery and application process.

The evaluation documents how each institution currently presents admissions information, where it creates friction, where data is fragmented across domains, and what the status tracking phase looks like from the outside. These are the gaps DirectPass is designed to address: this report maps their current shape and depth across four institutions.

Methodology

This evaluation was produced using a research pipeline with multiple stages and AI support. Foundational research was gathered via Perplexity, followed by automated live site walkthroughs using Playwright MCP + Chromium. Prior UI analyses for NYU and UBC, along with all supporting data, are documented in the DirectPass UX Research Spreadsheet ↗. All content was manually confirmed before inclusion. Report authored with Claude Code Opus 4.7; analysis text processed by GPT 5.5.

Platforms Reviewed

  • Desktop: 1440×900 viewport
  • Mobile: 390×844 viewport (comparable to an iPhone)

Methods Used

  • Competitive analysis
  • Screen flow review
  • Feature comparison matrix
  • Lightweight heuristic analysis
  • UI pattern review
  • Screenshot documentation

Tools & AI Pipeline

  • Playwright MCP + Chromium: automated live browsing, viewport resizing (1440×900 desktop / 390×844 mobile), and screenshot capture across all four sites
  • Navigation fidelity: every page reached via actual navbars, expanded menus, section navigation panels, and footer links; no direct URL shortcuts
  • Perplexity: foundational research layer; used to gather institutional background, enrolment data, and international student statistics prior to live site walkthroughs
  • Manual confirmation: each screenshot and navigation path was verified by a human reviewer before being included in the report
  • Claude Code Opus 4.7: HTML report file authored and structured from beginning to end via Claude Code CLI
  • GPT 5.5: data processing, text analysis, and written content generation for institution profiles and evaluation commentary
  • Prior UI analyses (NYU & UBC): supporting PDF documents reviewed alongside other sources; source data also available in the DirectPass UX Research Spreadsheet ↗

Institution Analysis

05.1

New York University

United States · Research University · nyu.edu

PDF UI analysis used as source

Homepage Analysis

  • First impression: Strong visual identity with NYU's signature violet. Hero is editorial and focused on brand expression, but international student pathways are not immediately visible.
  • Navigation: Left sidebar pattern is distinctive and functional. Horizontal tabs, flyouts, and dropdowns create a multilayered system that experienced users navigate well but newcomers may find dense.
  • CTAs: "Apply" and admissions CTAs are present but require scanning to locate. No prominent "International Students" primary CTA on the homepage.
  • Information hierarchy: Institutional brand and news are prioritized over pathways based on student needs. Content is rich but visually flattened: everything carries equal weight.

Application Workflow

  • Admissions entry point is reachable via main navbar. Page presents 10 equally weighted options with no recommended starting point.
  • International vs. domestic distinction is not surfaced early: users must identify themselves and locate the correct pathway.
  • Requirements, deadlines, and sequential guidance exist but are distributed across multiple supporting pages requiring several clicks.
  • Friction level: High. No sequential flow is presented. Users must construct their own path from a flat list of links.

International Student Resources

  • NYU hosts a large international population and does provide dedicated resources, but they require deliberate searching to find.
  • Visa guidance, English proficiency requirements, and tuition info for international students exist in supporting sections.
  • No consolidated "Start here as an international student" landing experience on the main site.
  • Research page presents AI and engineering content equally weighted with no filter based on student needs.

Mobile Experience

  • Mobile layout collapses the sidebar into a hamburger menu. Navigation becomes deeply nested on mobile.
  • Key CTAs are accessible but require scrolling or menu drilling to reach admissions content.
  • Text density remains high on mobile: dense paragraphs are not reformatted for small screens.
  • Overall: functional but not optimized. A prospective student researching on mobile faces more friction than on desktop.

05.2

University of British Columbia

Canada · Research University · ubc.ca

PDF UI analysis used as source

Homepage Analysis

  • First impression: Clean, minimal header. UBC's brand is understated: the homepage leads with editorial photography and a spotlight section rather than clear student CTAs.
  • Navigation: Top navbar with 9 main links is clean. An "Admissions" item links directly. A secondary audience navigation bar adds another layer.
  • Footer: Exceptionally well organized: divided into clear sections (About UBC, UBC Campuses) with legal links. One of the clearest footer structures observed.
  • International visibility: No dedicated "International Students" CTA on the homepage. Navigation to international content requires 2 to 3 clicks minimum.

Application Workflow

  • The admissions page on ubc.ca links to you.ubc.ca: a separate subdomain. This creates a context shift and potential disorientation.
  • The you.ubc.ca admissions hub is rich in content and includes study permit links, orientation deadlines, and program info.
  • International students can find study permit guidance, but it is mixed with domestic content: no separated pathway.
  • Admissions page mixes undergraduate programs, graduate admissions, tuition, scholarships, and readiness links all at equal weight.
  • Friction level: Moderate to high. Information exists but is spread across two domains and many equally weighted sections.

International Student Resources

  • Study permit guidance is available on you.ubc.ca with clear instructions on timing and process.
  • Tuition and financial planning tools exist within the admissions hub.
  • No dedicated "International Students" primary section on the main ubc.ca site.
  • Typography inconsistency across pages: underlined headings, varying font sizes, light blue background boxes competing with white content areas reduce visual coherence.

Mobile Experience

  • Main navbar collapses cleanly. UBC's mobile navigation is one of the more functional of the four sites tested.
  • The top navbar disappears on scroll: no sticky navigation. Users on long pages lose their primary wayfinding anchor.
  • Admissions content is readable on mobile, but dense text blocks on the UBC admissions page require full reading rather than scanning.
  • Footer contact information remains accessible on mobile.

  • Request information CTA is persistent across the admissions site: low friction path to getting personalized guidance.

Mobile Experience

  • Mobile homepage is clean with the flyout nav accessible via a single tap. Navigation closes properly and does not trap users.
  • The admissions site on mobile maintains the top nav with key actions. "Request Info" and "Contact Us" are accessible without excessive scrolling.

  • One of the better mobile experiences across the four sites tested.

Heuristic Analysis Summary

This evaluation applies 5 of Nielsen Norman Group's 10 Usability Heuristics, the subset most relevant to informational and navigational websites evaluated from a prospective student's perspective. The five omitted heuristics (H6 User Control & Freedom, H7 Error Prevention, H8 Flexibility & Efficiency of Use, H9 Aesthetic & Minimalist Design, H10 Error Recognition & Recovery) apply primarily to transactional interfaces, forms, portals, and systems where users take actions that can fail or be undone. Since this evaluation focuses on the research before application and navigation experience rather than the application portals themselves, those heuristics were intentionally excluded from scope.

Heuristic NYU UBC Northeastern Conestoga Pattern
H1: Visibility of Status 3 3 4 3 Breadcrumbs common; application progress rarely shown
H2: Match with Expectations 2 3 4 4 Better when student type is clearly segmented upfront
H3: Recognition Over Recall 2 3 4 3 Deadlines and costs rarely surfaced early enough
H4: Consistency and Standards 4 3 4 3 Most sites consistent on main site; supporting domains introduce inconsistency
H5: Help and Documentation 3 4 5 4 Contact and FAQ exist on all; Northeastern leads with persistent CTA
Average 2.8 3.2 4.2 3.4

Interpretation

Across all four sites, H3 (Recognition Over Recall) is the weakest pattern: deadlines, costs, and international requirements are rarely surfaced early. Students must navigate deep into supporting sections to find what they need to make a decision.

H5 (Help and Documentation) is the strongest pattern: all four sites provide contact and FAQ pages; Northeastern leads with its persistent action bar. This suggests institutions understand the importance of contact pathways but have not yet applied the same thinking to proactively surfacing key decision information.

The gap between Northeastern (4.2) and NYU (2.8) illustrates how much a focused admissions subdomain created for this purpose can improve the heuristic quality of the experience.

Key Findings

01

International student information exists but is fragmented

+
Observation

All four sites provide international student resources: visa guidance, tuition, requirements. However, the information is scattered across supporting sections, subdomains, and separate "International" sections that require deliberate discovery.

Evidence

NYU: no dedicated international homepage CTA. UBC: split between ubc.ca and you.ubc.ca. Northeastern: international page 3 levels deep. Conestoga: international section siloed from main admissions.

UX Implication

For DirectPass, this fragmentation is the structural problem the platform directly addresses: students arrive having already encountered these scattered pathways, and the platform's value depends on consolidating what institutions have not.

02

Application workflows are strongest when sequential and organized into steps

+
Observation

Sites that present the application as a sequential, numbered process significantly reduce user friction compared to sites that present a flat list of options.

Evidence

Northeastern's "How to Apply" with sequential steps is the clearest. Conestoga is second. NYU's admissions page with 10 options with equal weight has the highest perceived friction.

UX Implication

For DirectPass, the sequential model is the established baseline: the question is how to normalize it across institutions that present their process differently. Northeastern sets the benchmark; NYU demonstrates the cost of not having one.

03

Mobile navigation is a significant early research barrier

+
Observation

International students often begin research on mobile: from their home country, across time zones, on different devices. Mobile navigation quality directly affects first impressions.

Evidence

NYU: deeply nested mobile nav. UBC: no sticky nav, orientation loss on scroll. Conestoga: complex expanded menu. Northeastern: clearest mobile experience with accessible CTAs.

UX Implication

Students who arrive at DirectPass after a frustrating mobile experience on institutional sites bring that anxiety with them. The mobile experience of DirectPass is where that friction must be visibly resolved: the contrast is the value signal.

04

Trust increases when key information is visible early

+
Observation

Sites that surface deadlines, costs, requirements, and support contacts within the first 2 clicks build faster trust. Hiding this information signals institutional complexity over student readiness.

Evidence

Northeastern surfaces application deadlines on the admissions homepage. Conestoga surfaces tuition in the International section. NYU and UBC require deeper navigation for the same information.

UX Implication

For DirectPass, surfacing international tuition, deadlines, and eligibility criteria as immediate, default data, rather than buried in supporting pages, is the direct answer to what all four sites fail to provide. This is not a feature to add; it is the baseline expectation students bring having already been failed by institutional sites.

05

Student centered language reduces uncertainty and increases confidence

+
Observation

Sites using language organized around student questions ("How do I apply?", "What will it cost?") outperform sites organized around institutional departments and categories.

Evidence

Northeastern uses oriented around tasks labels: "Apply", "Cost & Financial Aid", "Student Life." UBC uses institutional labels: "Academics", "Research", "Strategic Directions."

UX Implication

The contrast between Northeastern's oriented around tasks labels and UBC's institutional categories confirms that language organized around student intent outperforms departmental structure. DirectPass should validate its own navigation labels against this benchmark: not against how institutions have named their own sections.

10

UX Opportunities for DirectPass

01

The fragmentation gap is DirectPass's core value proposition

Gap observed

Every site in this evaluation buries international student information across supporting sections, subdomains, and separate flows. None provides a consolidated view of the tasks an international student actually needs to complete.

DirectPass implication

This is not a gap to recommend universities fix: it is the gap DirectPass exists to close. The evaluation confirms that the problem is structural and consistent across institutions, which means students will reliably arrive at DirectPass with unresolved information needs.

Design consideration

The information architecture of DirectPass must be organized around student decision milestones: not around how each institution has chosen to structure its own site. The contrast between what universities surface and what students need should be invisible to the user.

02

Application status tracking fills the most critical missing layer

Gap observed

No university site in this evaluation provides any application status visibility beyond a link to an external portal. Once a student submits, the institutional website has no further role: they are handed off to separate systems (CommonApp, OUAC, institutional portals) with no continuity.

DirectPass implication

The phase after submission, where students wait for decisions, track document requirements, and manage multiple applications simultaneously, is entirely unserved by the websites evaluated. This is where DirectPass's tracking layer has no direct competition from any of the four institutions reviewed.

Design consideration

Status tracking should map directly to the specific steps each institution actually uses: not generic stages. The data gathered in this evaluation (what NYU, UBC, Northeastern, and Conestoga each require at each step) is directly usable as the schema for tracking flows for each institution.

03

Sequential step design is the proven low friction pattern

Gap observed

The clearest finding from this evaluation is that Northeastern's sequential "How to Apply" layout outperforms NYU's flat list of 10 options on every measured dimension. The pattern is consistent: when the process is presented as ordered steps, students understand what to do next.

DirectPass implication

Any view inside DirectPass that represents an application process, whether for a single school or across multiple, should follow a step model, not a link list. The benchmark is already established by Northeastern; the question for DirectPass is how to apply it across institutions with different process structures.

Design consideration

Each institution's process has a different number of steps and different naming conventions. DirectPass needs a normalization layer that maps processes specific to each institution into a consistent sequential UI: while preserving the specific details that matter to students applying to each school.

04

Domain fragmentation in institutional sites reveals data sourcing risk

Gap observed

UBC splits its admissions content across ubc.ca and you.ubc.ca, with visual inconsistency and no clear ownership signal. Northeastern uses admissions.northeastern.edu as a distinct subdomain. NYU and Conestoga both have information distributed across multiple levels. No institution maintains a single, canonical source for all the data a student needs.

DirectPass implication

DirectPass cannot rely on scraping a single page per institution to populate its data. Relevant information, deadlines, requirements, visa guidance, costs, lives at different URLs and may be inconsistently maintained. This evaluation maps exactly where that data lives for each of the four institutions reviewed.

Design consideration

Data sourcing, freshness, and conflict resolution between multiple institution URLs is a product infrastructure concern that should be addressed early: not as a feature, but as a reliability requirement. Students trust DirectPass to have accurate information; that trust depends on understanding where each institution actually publishes authoritative data.

05

Deadlines and costs are the most consequential scannable data points

Gap observed

Across all four sites, application deadlines and cost information require multiple clicks to surface. Northeastern is the exception: its Cost & Financial Aid is a primary nav item. All four institutions treat financial and deadline data as secondary discovery, not primary decision support.

DirectPass implication

Deadlines and costs are likely the two most data points checked most often students return to DirectPass to check. They should be present on every view for each school in the platform, without requiring the user to navigate anywhere. This evaluation confirms what is missing from every institutional website: and that absence is what makes these data points especially valuable for DirectPass to own.

Design consideration

Deadline display should account for timezone (students applying from outside North America face real deadline confusion). Cost display should clearly separate domestic vs. international tuition, since most institutional sites present domestic figures by default: a silent failure mode this evaluation observed in all four cases.

11

Recommendations for DirectPass

Specific decisions this evaluation should inform in the DirectPass product: grounded in what was directly observed across these four institutions.

01

Model data for each institution around actual URL structure, not assumed structure

This evaluation confirmed that each institution distributes key information across multiple subdomains and sections. For NYU, UBC, Northeastern, and Conestoga, the actual source URLs for deadlines, costs, visa requirements, and program details are documented in this report and the linked research spreadsheet. Data models for these institutions should reflect the real source structure, not a generic template.

02

Use Northeastern's step model as the process normalization benchmark

Of the four institutions evaluated, Northeastern's "How to Apply" is the clearest sequential representation of an application process. When designing DirectPass's application flow view for each institution, Northeastern's structure is the most legible reference: not because it should be copied, but because it already maps closely to how students think about the process.

03

Treat UBC's domain split as a specific edge case in data sourcing

UBC is the only institution in this evaluation where critical admissions content (study permit guidance, application steps) lives on a different registered domain from the main site (you.ubc.ca vs. ubc.ca). DirectPass needs to handle this explicitly: not just as a data fetch, but as a trust and attribution signal for users who will notice the URL difference.

04

Deadline and cost display must default to international figures

All four institutions present domestic tuition and deadline information by default. International figures require a separate page or section. DirectPass, serving only international students, must ensure that every deadline and cost displayed is unambiguously the international figure: not the domestic one with a footnote.

05

The phase after submission has no institutional equivalent: own it clearly

None of the four websites provides any tracking, status, or guidance after a student clicks "Apply." That entire phase, document verification, decision timelines, offer response, is handed off to external portals. This is the phase where DirectPass's tracking functionality operates with no direct competition from institutional sites, and it should be the sharpest part of the product experience.

06

Conestoga's international section is the content model for what to consolidate

Despite its discoverability problem, Conestoga's international section is the most complete single page consolidation of what a student needs: study permit, tuition, admission requirements, student services. The content structure, not the navigation, is worth mapping directly as an input to what DirectPass should aggregate per institution.

07

Deadline display that accounts for time zones is an unmet need across all four sites

No site in this evaluation accounts for the timezone of the student reading it. A student in India reading "deadline: November 1" has no way to know whether that means EST, the institution's local time, or midnight UTC. For DirectPass serving users across time zones, deadline display should be explicit about the reference timezone: this is a gap none of these institutions have addressed.

08

NYU's flat admissions structure reveals what anxiety looks like for tracked applications

NYU presents 10 equally weighted options with no recommended path. This was the pattern observed with the greatest friction. For students who have applied to NYU, DirectPass's status view for that application should compensate directly: clear current stage, specific next action, and document checklist. The anxiety this evaluation observed in NYU's navigation is the exact anxiety that DirectPass's tracking layer must eliminate for active applications.
